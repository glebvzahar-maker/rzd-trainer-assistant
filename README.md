# Ассистент тренера РЖД

Одностраничный каталог разминок, ледоколов и инструментов фасилитации
для проведения образовательных мероприятий с руководителями РЖД.

Открывается двойным щелчком по `index.html` — сборка, зависимости и сервер не нужны.

## Что внутри

**76 активностей** в пяти форматах:

| Формат | Упражнений | Для чего |
|---|---:|---|
| Ледоколы | 21 | снять напряжение первой встречи |
| Энерджайзеры | 26 | зарядить группу физически и эмоционально |
| Рефлексия | 10 | осмыслить опыт, подвести итоги |
| Активности | 9 | отработать навык или профессиональную задачу |
| Фасилитация | 10 | провести мероприятие целиком |

Источники: материалы РЖД (22), книга М. Кипниса (15), книга Н. Еремеевой (13),
мировая практика (16), инструменты фасилитации (10).

У каждой активности, помимо инструкции, есть подсказка ведущему, адаптация
на другую численность группы, требования безопасности (где они нужны),
ключ ответов (для викторин) и контекст — притча или определение метода.

## Возможности

- фильтры по времени, источнику, формату, типу, длительности и размеру группы
- поиск по названию, цели, бизнес-связке, шагам, материалам и подсказке
- конструктор сценария с суммарным таймингом, экспортом и печатью
- таймер с неблокирующим уведомлением, чек-лист подготовки с сохранением
- три темы: светлая, «для солнца» и тёмная, переключаются в шапке
- работа с клавиатуры, чтение с экрана, печать на бумагу

### Таймер

Отсчёт идёт от абсолютного дедлайна, а не от счётчика, поэтому:

- таймер переживает перезагрузку страницы — время, прошедшее пока вкладка была
  закрыта, вычитается;
- фоновая вкладка не сбивает отсчёт: браузер душит таймеры в фоне, а значение
  всё равно считается от дедлайна;
- остаток дублируется в заголовке вкладки, чтобы он был виден, когда тренер
  переключился на другую вкладку;
- открытая карточка упражнения показывает отсчёт в липкой шапке: панель таймера
  лежит под модальным окном и без этого была бы не видна.

### Печать

Кнопка «Печать» в сценарии и кнопка «🖨 Печать» в карточке упражнения печатают
собственный лист, а не каталог:

- **сценарий** — список упражнений с таймингом, целью, материалами, требованиями
  безопасности, подсказками и ключами ответов;
- **карточка** — инструкция целиком, ключ для ведущего в рамке и пометка, что
  документ нельзя раздавать участникам.

Обычная печать каталога (Cmd/Ctrl+P) работает как раньше и печатает сетку карточек.

### Ссылки на подборку

Состояние фильтров пишется в адресную строку, поэтому подборку можно дать
ссылкой: `?s=rzd&f=activity&q=поезд`. Значения проверяются по реальным
элементам управления: ссылка с неизвестным параметром открывает полный каталог,
а не пустой результат.

## Сборка каталога

Каталог `Активности_для_лендинга.md` не ведётся вручную, а генерируется
из данных лендинга, поэтому разойтись с ним не может:

```bash
node .validate_extract.py && node /tmp/ex_check.js   # целостность данных
python3 .build_catalog.py                            # пересобрать .md
python3 .verify_sync.py                              # проверить соответствие
python3 .verify_contrast.py                          # проверить темы
node deploy/build-gate.mjs                           # собрать функцию для Vercel
node deploy/build-pages.mjs --password 3321          # собрать страницу для Pages
```

## Публикация

Две площадки, каждая со своим способом закрыть вход.

| | Vercel | GitHub Pages |
|---|---|---|
| Ссылка | https://rzd-trainer-assistant.vercel.app | https://glebvzahar-maker.github.io/rzd-trainer-assistant |
| Где проверяется пароль | на сервере, в serverless-функции | в браузере, на странице |
| Каталог без пароля | **не отдаётся вообще** | лежит в том же файле и читается без входа |
| Что защищает | закрывает содержимое от посторонних | закрывает от случайного взгляда, но не от того, кто умеет смотреть исходник |

Репозиторий публичный: https://github.com/glebvzahar-maker/rzd-trainer-assistant

Это сделано осознанно. Разница в защите — принципиальная, а не в степени:

- **Vercel** проверяет пароль на сервере. Без верного пароля страница не
  отдаётся вообще: каталога нет ни в ответе, ни в исходнике страницы.
- **GitHub Pages** раздаёт статику и проверить пароль на сервере не умеет.
  Форма входа закрывает каталог для обычного посетителя, но сам каталог лежит
  в том же файле — и репозиторий публичный, поэтому тот, кто целенаправленно
  его скачает, получит содержимое без всякого ввода.

Для рабочего инструмента тренера этого достаточно; если каталог потребуется
держать закрытым по-настоящему, Vercel для этого и оставлен.

### GitHub Pages: публикация

Страница собирается из `index.html` с включённым входом по паролю:

```bash
deploy/publish-pages.sh 3321     # собрать и запушить в ветку gh-pages
```

Скрипт собирает страницу (`deploy/build-pages.mjs`) и обновляет ветку
`gh-pages`, из которой Pages и раздаёт сайт. Сборка занимает около минуты.

Что внутри собранной страницы:

- каталог закрыт до ввода, пароль сверяется с PBKDF2-SHA256 (210 000
  итераций, около 35 мс на телефоне) против соли и хеша;
- сам пароль в файле не хранится — только соль и хеш;
- вход запоминается в браузере на 30 дней;
- в исходном `index.html` гейт выключен: локальный файл открывается без
  пароля, а на Vercel пароль проверяет serverless-функция.

Пароль можно поменять: `deploy/publish-pages.sh <новый>`.

### GitHub Pages: автопубликация

Воркфлоу `.github/workflows/pages.yml` собирает и публикует страницу сам при
каждом пуше в `main`. Он лежит в ветке `pages-workflow` и в рабочей папке, но
не в `main`: GitHub не пускает файлы `.github/workflows/` при push токеном без
scope `workflow`, а блокировать `main` целиком не хочется.

```bash
gh auth refresh -h github.com -s workflow   # подтвердить в браузере
git cherry-pick pages-workflow              # забрать воркфлоу в main
git push origin main
```

Пароль для воркфлоу берётся из секрета репозитория `GATE_PASSWORD`
(Settings → Secrets and variables → Actions), а не из файла.

### Vercel: как устроена защита

Штатная парольная защита Vercel доступна только на тарифе Pro ($20/мес за
проект), а аккаунт на Hobby. Поэтому доступ закрыт собственной serverless-функцией
в `deploy/`:

- страница **встроена в функцию** и не существует как статический файл — обойти
  шлюз запросом файла нельзя;
- пароль сравнивается за постоянное время, хранится только в переменной
  окружения `GATE_PASSWORD`;
- при успехе выдаётся cookie с HMAC-подписью: `HttpOnly`, `SameSite=Strict`,
  `Secure`, срок 12 часов, подделать или продлить без секрета нельзя;
- после 8 неудачных попыток вход блокируется на 5 минут с заголовком `Retry-After`;
- ответы помечены `no-store` и `X-Robots-Tag: noindex`.

Известные ограничения: счётчик попыток живёт в памяти экземпляра и обнуляется
при его перезапуске, поэтому защита останавливает перебор, но не заменяет
ограничение по IP на уровне сети. Смена пароля — передеплой.

Текущий пароль: **3321**.

### Vercel: правка и передеплой

```bash
# после изменений в index.html
node deploy/build-gate.mjs

cd deploy
vercel --prod --yes
```

Смена пароля:

```bash
cd deploy
vercel env add GATE_PASSWORD production --value <новый> --sensitive --force
vercel --prod --yes
```

Если деплой отклоняется со статусом `BLOCKED` и сообщением *«the commit author
doesn't have permission to create deployments»* — Vercel сверяет адрес автора
последнего коммита с подтверждённым адресом аккаунта. Проверьте:

```bash
git config user.email   # должен совпадать с адресом аккаунта Vercel
```
